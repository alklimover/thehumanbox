# Тексты симуляции: извлечение, частотность и перевод (этап 0.4)

Тексты симуляции — это мысли людей, события, летопись жизни, воспоминания, заголовки, вехи и названия. Они пишутся по-английски внутри симуляции на Rust. По [плану](PLAN.ru.md) Rust не трогаем и переводим текст при показе. Этот документ описывает основу для перевода: что и где пишет симуляция и что из этого реально видит игрок.

## Скрипты

Скрипты лежат в `scripts/i18n/`. Результаты пишутся в `scripts/i18n/out/` (папка не в git).

| Скрипт | Что делает | Время |
|---|---|---|
| `extract-sim-strings.mjs` | Обходит `crates/sim-core/src` и собирает каталог: каждая строка и шаблон `format!`, канал, места в коде. Пишет `out/sim-catalog.en.json`. | ~0,4 с |
| `measure-frequency.mjs` | Гоняет WASM-симуляцию игры на нескольких мирах параллельно и считает, какие тексты видит игрок. Пишет `out/sim-frequency.json`. | ~2 мин на 8 миров × 20 тыс. тактов |
| `sim-coverage.mjs` | Сопоставляет увиденное с каталогом: полнота, кривая покрытия, ненайденное. С `--tsv` пишет записи каталога по убыванию частоты. | <1 с |
| `sim-strings-diff.mjs` | Новые тексты симуляции между двумя коммитами. Его вызывает отчёт еженедельной синхронизации с оригиналом. | ~2 с |
| `rust-tokens.mjs` | Токенизатор Rust для экстрактора. | — |

```sh
scripts/build-wasm.sh                      # если WASM ещё не собран
node scripts/i18n/extract-sim-strings.mjs
node scripts/i18n/measure-frequency.mjs --seeds 1,2,3,4,5,6,7,8 --ticks 20000
node scripts/i18n/sim-coverage.mjs --tsv docs/fork/simtext/frequency-ranked.tsv
```

Проверки: `apps/web/src/i18n/simtext/extractor.test.ts` (входят в обычный `pnpm test`).

### Как работает извлечение

Rust не парсится целиком. Токенизатор понимает комментарии, экранирование, raw-строки, символы и lifetime. Поверх токенов ведётся стек открытых скобок. Так для каждой строки известно, внутри какого вызова или поля структуры она стоит и каким по счёту аргументом. Через `format!`, `to_string`, `Some(…)` и кортежи поиск идёт насквозь.

**Каналы по месту в коде:**

| Канал | Откуда |
|---|---|
| `thought` | `think(…)`, `set_thought!(…)` |
| `event:<вид>` | `event(вид, текст)`, `push_event(…, вид, кто, текст)`, `discover(что, текст)` (вид `build`) |
| `life:<категория>` | `log_life(…)`, `log_life_rel(…)`, `log_event(…)` |
| `memory` | `MemoryEntry::new(…)` |
| `headline` | `headlines.push_back(…)` / `push(…)` |
| `field:<поле>` | поля структур `name`, `title`, `text`, `detail` и т. п. |
| `event-actor` | кто совершил событие («the river», «a wildfire») |
| `other` | текст, который доходит до игрока через переменную или таблицу |

Отдельно от каналов текст делится по виду: обычная строка, шаблон `format!` (`{name} founded a village`) и склейка без слов вроде `{label}: {text}`. Одиночное слово вне известного места хранится отдельно: это может быть id, а может быть кусок составного текста.

Записи из массива вариантов (`["foraging", "looking around", "roaming"]`) считаются текстом целиком, если в массиве есть хотя бы одна фраза.

**Что пропускается:** тестовые модули `#[cfg(test)]`, папки `tests/`, файлы `tests.rs` и `*_tests.rs`, а также `println!`, `assert!`, `panic!`, `.expect("…")`. Файлы `forge_test.rs` и подобные пропускать нельзя: это действия людей («закалка», «проба брожения»).

## Что видит игрок

Замер: 8 миров (seed 1–8) по 20 000 тактов, срез кадра каждые 200 тактов, на каждом срезе открываются карточки 12 случайных людей.

Что считается показом:
- мысль над головой — на каждом срезе, поэтому частые мысли весят больше;
- событие, заголовок, веха, название — один раз;
- запись летописи, недавняя мысль и воспоминание — один раз у каждого открытого человека.

Итого 930 441 показ и 111 351 разный текст (вместе с подставленными именами и числами).

Первые строки списка: «resting under shelter», «wandering», `heard that {actor_name} {detail}`, «chopping wood», `found and ate food at ({cx},{cy})`, `brought home a {arg0}`.

### Чего каталог не объясняет

- **Религии:** «First Word rel10» — название из `RELIGION_NAMES` и внутренний id через пробел. Нужно правило: перевести название по таблице, id убрать или оставить.
- **Названия книг:** `pick_book_title` склеивает префикс и тему из двух таблиц (`BOOK_TITLE_PREFIX` × `BOOK_TITLE_TOPIC`), переводятся парой таблиц. Названия картин — шаблон `Untitled {kind} no.{id}`, он в каталоге.
- **Двухуровневые размышления:** `{mood}{asp_line}: {frame}`, где `frame` = `I remember — {текст воспоминания в нижнем регистре}`. Нужен отдельный разборщик (`reflect_internally` в `organism/organism/inner.rs`).
- **Речь на языке племён:** `"vo" (1/1)` — выдуманные слова, переводить нечего.

## Выводы для слоя перевода (шаг 3)

1. **Ключ — «канал + текст».** 4 314 строк используются одновременно как мысль и как событие: действие пишет `think("write journal")` и `event("life", "write journal")`. По-русски это разные формы: «пишет дневник» и «писал(а) дневник».
2. **Род действующего лица.** В событиях и летописи около 40 % показов — прошедшее время без подлежащего («built a navigation cairn», «crafted {what} for the first time»). Ещё большая часть — названия действий («write poem», «guard flock»). В ленте событий имя показывается отдельно (`actor`), в летописи человек известен. Род берём из данных человека.
3. **Вложенные фразы.** Третья по частоте запись — `heard that {actor_name} {detail}`, где `detail` — текст другого события. Так же устроены «{name} is gone. What they carried: "{воспоминание}"», заголовки `🧬 {строка}`, `{milestone}: {описание}` и `I remember — {…}`. Нужна рекурсия: подстановку сначала искать в каталоге, учитывая, что вложенная фраза бывает с заглавной буквы или в нижнем регистре без точки. Сопоставитель в `sim-coverage.mjs` уже так работает, его можно взять за основу.
4. **Существительные в шаблонах и падежи.** Частые подстановки: `{what}` / `{arg0}` (товары и поделки: `brought home a {arg0}`), `{kind}`, `{cargo}`, `{building}`. Для них нужны падежные формы в таблицах `simLabel` (как минимум винительный падеж).
5. **Имена, числа и id** подставляются как есть. Координаты в летописи (`found and ate food at ({cx},{cy})`) — частые записи, но переводить в них нечего.
6. **Оригинал добавляет тексты постоянно:** за 2,5 недели — 233 новых текста симуляции (54 события, 27 мыслей, 16 записей летописи и др.). Еженедельный отчёт синхронизации показывает их через `sim-strings-diff.mjs`.

## Слой перевода (шаг 3)

Код лежит в `apps/web/src/i18n/simtext/`. Интерфейс зовёт `simText(канал, текст, { sex })` там, где показывает текст симуляции:

- мысль над головой (`people-labels.ts`) и в карточках;
- недавние мысли, увиденное, воспоминания, история жизни;
- лента событий (пол берётся по имени действующего лица);
- лента новостей, летописи, легенды, уведомления приложения;
- подписи людей в интерьерах.

Симуляция и вся логика по-прежнему видят английский текст. В английском интерфейсе `simText` возвращает текст как есть.

**Таблицы** — `ru/thoughts.ts`, `ru/actions.ts`, `ru/events.ts`, `ru/memories.ts`, `ru/headlines.ts`. Описания вех берутся из уже переведённой `i18n/sim/milestone.ts`. Ключ — английский текст или шаблон из каталога (`heard that {actor_name} {detail}`). Шаблон можно сузить до одного значения: `mentored by elder {org_name}`.

**Значение записи** — строка или `{ thought, event }`, когда одна английская фраза служит и мыслью, и событием. Мысль пишется в настоящем времени, событие — в прошедшем.

**Разметка в русском тексте:**

| Разметка | Что делает |
|---|---|
| `построил[а]` | окончание женского рода |
| `[пошёл\|пошла]` | обе формы целиком; обязательно, если женская форма меняет основу (тест не пропустит `принёс[ла]`) |
| `{detail}` | значение переводится рекурсивно как текст того же канала; имена и числа остаются как есть |
| `{detail@actor_name}` | вложенный текст берёт пол человека по имени из `actor_name` |
| `{what\|good}` | значение — id, показывается через `simLabel('good')` |

Если пол неизвестен, видны обе формы: «построил(а)», «пошёл/пошла».

**Размышления** («feeling light, a provider at heart: I remember — …») собираются в симуляции из нескольких частей. Их разбирает отдельная функция в `index.ts`.

**Проверки** (`tables.test.ts`, входят в `pnpm test`):
- каждый ключ должен совпадать с текстом, который действительно пишет симуляция: экстрактор запускается прямо в тесте. Опечатка или переписанная автором фраза роняет тест, а не показывает тихо английский;
- плейсхолдеры в переводе есть в ключе, домены `simLabel` существуют;
- в переводе нет латиницы, скобки разметки сбалансированы.

**Покрытие** по замеру (8 миров × 20 000 тактов): **96,3 % показов** текста симуляции на русском.

| Канал | Покрытие |
|---|---:|
| заголовки | 100 % |
| летопись | 97,8 % |
| мысль над головой | 97,6 % |
| воспоминания | 97,0 % |
| недавние мысли | 96,8 % |
| события | 94,7 % |

Остаток — длинный хвост редких фраз. Названия книг и картин, имена религий с id и описания эпох пока остаются английскими.
